# E6 — Validation and release readiness

**Priority:** P1
**Depends on:** E0–E5
**Goal:** Validate the design with target users and make build/release work traceable.

## Tasks

- [ ] **E6.1 Build a low/high-fidelity prototype.** Include workspace invite,
  public/private channel paths, composer, thread, and failed-send states.
- [ ] **E6.2 Run five target-team usability sessions.** Capture completion,
  confusion, access-control expectations, and attention/notification feedback.
- [ ] **E6.3 Define success instrumentation.** Activation, time-to-first-message,
  search success (when built), reliability, and retention measures without content.
- [ ] **E6.4 Resolve findings.** Track severity, decision, owner, and document
  revision; do not bury changes in prototype-only notes.
- [ ] **E6.5 Produce handoff pack.** Link designs to entities/actions/tests and
  mark open questions/blockers.
- [ ] **E6.6 Release-readiness review.** Verify migration strategy, CI, privacy
  copy, threat model, accessibility, and support/runbook ownership.

## Acceptance criteria

- Critical usability/security findings have a recorded disposition.
- A future implementer can trace each capability to design, data, action, and test.
- The release checklist identifies items not ready to claim publicly.
